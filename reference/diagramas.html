1. A Analogia do Veículo (Passageiro vs. Motorista vs. Veículo)

A metáfora que explica por que a Harness importa mais do que o modelo isolado.

[ Você (Passageiro) ] │ (Dá a direção e objetivos da demanda) ▼ [ Modelo LLM (Motorista) ] ── (Pesos treinados, raciocínio, capacidade de previsão) │ ▼ [ Agent Harness (Veículo Equipado) ] ├── Ferramentas e Sensores (Leitura de arquivos, terminal, compilador) ├── Protocolos de Extensão (MCP, APIs locais) └── Barreiras de Proteção (Sandbox, hooks, guardrails anti-slop)

Lição aprendida: Colocar um piloto experiente em um carro desgovernado causa acidentes. Dar um veículo com telemetria e piloto automático a um motorista júnior permite cruzar a cidade com segurança.

2. Esteira Completa de Inferência Local

O pipeline de software que conecta o arquivo de pesos no disco até as ferramentas do seu editor.

[ Arquivo .gguf (Pesos) ] │ (Quantizado em Q4/Q8 no disco) ▼ [ Motor de Inferência (llama.cpp / LM Studio) ] ├── Carregamento de tensores na VRAM da GPU (ou offload na RAM) ├── Gerenciamento do KV Cache (memória de curto prazo) └── Exposição do Servidor HTTP na porta local (ex: localhost:18080/v1) │ ▼ (Protocolo compatível OpenAI /v1/chat/completions) [ Harness de Desenvolvimento (Claude Code, Cursor, Antigravity) ]

Lição aprendida: O modelo não tem olhos nem mãos. O motor de inferência faz o cálculo numérico e a harness injeta ferramentas para que ele altere o mundo real.

3. KV Cache: Memória Dinâmica vs. Espaço de VRAM

Por que o consumo de memória sobe durante a conversa mesmo com o modelo já carregado.

[ VRAM TOTAL DA GPU ] (ex: 8 GB) ┌──────────────────────────────────────────────┬───────────────────────────────┐ │ Pesos Fixos do Modelo (ex: ~4.5 GB) │ KV Cache Dinâmico (~2-3 GB) │ │ Alocados na inicialização (.gguf) │ Cresce com histórico e docs │ └──────────────────────────────────────────────┴───────────────────────────────┘ ▲ Prompt Prefill (lendo o arquivo do projeto) ┘ A cada novo token gerado, o histórico é armazenado no cache.

Lição aprendida: Deixar margem livre na VRAM para o KV Cache (ou quantizá-lo em Q4/Q8) impede que o modelo estoure a memória e caia para a lentidão da RAM do sistema.

4. Arquitetura MoE (Mixture of Experts) e Offload

Como rodar modelos gigantes (como 30B ou 70B) em placas de vídeo de entrada.

[ Prompt do Usuário ] ──► [ Camada de Roteamento (Router / Gating) ] │ ┌──────────────────┴──────────────────┐ ▼ (Ativa 2 Experts) ▼ [ Expert 1 (Código) ] [ Expert 2 (Lógica) ] (Na VRAM rápida) (Na VRAM rápida) │ │ [ Experts Inativos 3 a 8 ] (Descarregados na memória RAM do sistema)

Lição aprendida: Em MoE, apenas uma fração dos pesos é ativada por token. Os experts ativos rodam na VRAM enquanto os inativos podem aguardar na RAM sem congelar o computador.

5. Day / Night e a Fronteira de Pareto

A ausência de um "modelo perfeito único" e a escolha de dois pontos na fronteira de eficiência.

▲ Inteligência / Capacidade │ │ ● Night Model (Mais denso, raciocínio longo, sem supervisão) │ / │ / ◄─── Fronteira de Pareto Medida (Trade-off ótimo) │ / │ ● Day Model (Ultra rápido, 50+ TPS, supervisão humana ativa) │ └────────────────────────────────────────────────────────► Velocidade (TPS)

Lição aprendida: Durante o dia, use um modelo rápido com você no controle. À noite, configure um loop autônomo com um modelo mais analítico enquanto você descansa.

6. A Metáfora da Boate: Guardrails e Sandbox

Como proteger seus repositórios e produção de ações perigosas do agente.

[ Agente / Modelo ] ──► Tenta executar comando (ex: git push, rm -rf, ler .env) │ ▼ [ Segurança da Porta (Guardrails & Hooks) ] ├── Allow List: Comandos seguros liberados (cat, pytest, lint) ├── Deny List: Bloqueio imediato (env, reset --hard, chaves de API) └── Confirmação Humana: Parada obrigatória para ações irreversíveis

Lição aprendida: IAs locais menores podem cometer erros graves. Blindar o repositório com hooks no Git e sandbox impede que um vacilo quebre a sua infraestrutura.
